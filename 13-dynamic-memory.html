Динамическая память

Как выделить память во время работы программы, изменить её размер и вовремя освободить

Как пользоваться уроком

Вспомните указатели: указатель хранит адрес, а через *p или p[i] можно обращаться к данным по этому адресу. Теперь научимся получать память, размер которой выбирается во время работы программы.

Каждый блок с именем .c — отдельная полная программа. Сохраните один блок в файл и соберите, например: gcc -std=c11 -Wall -Wextra memory.c -o memory. Запускайте полученную программу из командной строки.

Цель: объяснить жизненный цикл блока — запрос → проверка → использование → освобождение, а также безопасное изменение размера через realloc.

01

Зачем нужна динамическая память

Размер и время жизни блока могут определяться во время выполнения.

Представьте список результатов: заранее неизвестно, сколько чисел потребуется хранить. Динамическое выделение позволяет запросить подходящее количество байтов, а затем при необходимости изменить размер блока.

Локальная переменная вроде int x = 5; существует в своей области действия согласно правилам автоматического времени хранения. Выделенный через malloc блок живёт до освобождения через free или успешного изменения через realloc. Даже если локальная переменная-указатель исчезнет, выделенный блок сам по себе не освободится.

УКАЗАТЕЛЬ И БЛОК — НЕ ОДНО И ТО ЖЕПеременная p хранит адрес; данные размещены в отдельном блоке. Можно передать адрес в функцию или скопировать указатель, но от этого блок не копируется и владельцем памяти нужно управлять явно.

Динамическую область часто называют «кучей», но стандарт C не требует конкретной организации памяти. Функции выделения и освобождения объявлены в <stdlib.h>.

02

malloc: выделяем память

Запрашиваем количество байтов и обязательно проверяем результат.

malloc(bytes) запрашивает блок размером bytes байтов и возвращает указатель на него. Если выделить ненулевой размер не удалось, результат — NULL. Содержимое нового блока не инициализировано: перед чтением значения нужно записать.

Вывод
Число: 42
  1. int *p — указатель на int. sizeof *p — число байтов, необходимых для одного int; сам p при вычислении sizeof здесь не разыменовывается.
  2. Результат проверяется до обращения к выделенной памяти. При неудаче программа сообщает об ошибке и завершает работу.
  3. *p = 42 записывает число по адресу из p, а printf читает его обратно.
  4. free(p) завершает время жизни блока. Присваивание p = NULL помогает не использовать этот указатель случайно; другие копии указателя от этого не изменятся.
ПОЧЕМУ НЕТ ПРИВЕДЕНИЯ ТИПА?В C указатель void *, возвращаемый malloc, автоматически преобразуется в int *. Для языка C запись (int *) здесь не нужна.
03

Динамический массив

Выделяем место для нескольких элементов и работаем с индексами.

Для n элементов типа int требуется n * sizeof *a байтов. В этой программе размер задаётся переменной: в реальном приложении его можно получить после проверки входных данных.

Вывод
10 20 30 40

size_t — беззнаковый тип для размеров объектов. SIZE_MAX из <stdint.h> — максимальное значение этого типа. Проверка перед умножением не позволяет запросить слишком маленький блок из-за переполнения вычисления размера.

Индексы здесь идут от 0 до n - 1. Выражение a[i] обращается к элементу в выделенном блоке. Указатель a сам по себе длину не хранит: размер нужно сохранять отдельно. Конкретное заполнение примера рассчитано на заданное n = 4, а не на произвольное большое значение.

sizeof УКАЗАТЕЛЯ — НЕ РАЗМЕР МАССИВАsizeof a даёт размер указателя, а не количество байтов, полученных от malloc. Для запроса используйте n * sizeof *a и храните n.
04

realloc: меняем размер блока

Блок может остаться на месте или переместиться; используем временный указатель.

realloc(p, new_bytes) изменяет размер ранее выделенного блока. При успехе сохраняются старые данные в пределах меньшего из старого и нового размеров; добавленная область не инициализирована. При неудаче запроса ненулевого размера возвращается NULL, а исходный блок остаётся выделенным и доступным через старый указатель.

Вывод
10 20 30 40 50

Разбор по шагам

  1. Сначала выделяем три элемента и записываем [10, 20, 30].
  2. Запрашиваем новый размер в пять элементов, сохраняя результат в temp. Проверяем умножение на размер элемента до вызова.
  3. Если temp == NULL, прежний блок всё ещё принадлежит программе: освобождаем его через free(a) и сообщаем об ошибке.
  4. При успехе обновляем a = temp. Первые три значения сохранены; ячейки с индексами 3 и 4 ещё нужно заполнить.
  5. Обновляем длину, выводим все пять элементов и освобождаем блок через новый указатель a.
НЕ ПИШИТЕ a = realloc(a, ... ) БЕЗ ВРЕМЕННОЙ ПЕРЕМЕННОЙПри ошибке такое присваивание заменит единственный адрес блока на NULL. Тогда освободить блок уже не получится: возникнет утечка памяти.

При уменьшении размера сохраняется только начало блока, которое помещается в новый размер; обращаться к удалённой части нельзя. После успешного realloc используйте возвращённый указатель и заново вычисляйте адреса элементов: старые указатели на блок и его элементы больше не действуют, даже если численный адрес совпал.

ОСОБЫЕ СЛУЧАИrealloc(NULL, size) при ненулевом размере работает как запрос нового блока. С realloc(p, 0) связаны зависящие от стандарта и реализации тонкости; вместо него явно вызовите free(p) и присвойте указателю NULL.
05

free: освобождаем память

Каждому выделенному блоку нужен понятный владелец и момент освобождения.

free(p) освобождает блок, начало которого было получено от malloc, calloc или успешного realloc и ещё не освобождено. Вызов free(NULL) допустим и ничего не делает.

  • После free(p) нельзя читать или записывать данные по старому адресу. Любые другие указатели в этот блок тоже становятся недействительными.
  • Нельзя повторно освобождать один и тот же блок, передавать free адрес локальной переменной или адрес элемента внутри блока, например &a[1].
  • Если потерять последний указатель на ещё выделенный блок, возникнет утечка памяти: программа больше не может его использовать или освободить.
  • При нескольких выходах из функции освобождайте уже полученные ресурсы и на пути ошибки. Каждому успешному выделению должно соответствовать освобождение, когда блок больше не нужен.
КОПИИ УКАЗАТЕЛЯЕсли int *q = p;, оба указателя относятся к одному блоку. После free(p); p = NULL; переменная q не становится NULL и больше не пригодна для доступа к блоку или его освобождения.
06

calloc, нулевой размер и размер в байтах

calloc(n, size) выделяет память для n элементов по size байтов и устанавливает все байты выделенного блока в ноль. Результат тоже нужно проверить и затем освободить через free. В отличие от malloc, где изначальное содержимое не определено, при calloc все биты блока нулевые. Для произвольных типов не следует считать, что нулевые биты обязательно означают корректное значение нулевого указателя или вещественного нуля на любой платформе.

Если размер вычисляется из внешних данных, сначала проверьте его допустимость, включая знак до преобразования в size_t, затем убедитесь, что n <= SIZE_MAX / sizeof *p. Только после этого умножайте. В наших примерах размер положительный; для запроса нуля байтов поведение результата выделения зависит от реализации, поэтому удобнее обработать пустой набор отдельно и не разыменовывать результат такого запроса.

ТРИ КОЛИЧЕСТВАn — число элементов; sizeof *p — байтов на один элемент; n * sizeof *p — общий размер блока в байтах.

Использовать p, не проверив mallocПри ошибке разыменование NULL недопустимо.Сразу проверить результат.
Прочитать элемент сразу после mallocЗначение ещё не инициализировано.Сначала записать каждый нужный элемент.
Обратиться к a[n]Это за пределами массива из n элементов.Использовать индексы 0 ... n - 1.

08

Самопроверка и практика

Задача 1. В программе dynamic_array.c измените заполнение так, чтобы элементы были 1 4 9 16. Какие индексы допустимы?
Показать подсказку

При заданном n = 4 запишите a[i] = (int)((i + 1) * (i + 1));. Допустимые индексы — 0, 1, 2, 3.

Задача 2. В программе resize_array.c расскажите, что произойдёт при ошибке выделения и почему нельзя использовать старый адрес после успешного realloc.
Показать ответ

При ошибке ненулевого запроса temp равен NULL, а старый блок остаётся доступным через a; программа освобождает его и сообщает об ошибке. При успехе используем только новый указатель: блок мог переместиться, а прежние указатели больше не действуют.

Задача 3. Выделите память под одно число, запишите в неё значение и передайте указатель в функцию, которая увеличит число на 1. Кто должен освобождать блок?
Показать подсказку

Функция может принять int *p и выполнить ++*p. Договоритесь о владении: например, main выделяет блок, проверяет результат, вызывает функцию и затем делает free(p).

Перед ответом у доски

  • Могу объяснить разницу между указателем и выделенным блоком.
  • Знаю, в каких единицах задаётся размер и почему проверяется переполнение.
  • Могу описать успех и неудачу malloc и realloc.
  • Могу показать, где и кем освобождается каждый блок, включая путь ошибки.

Главное в одном предложении

Проверяйте размер и результат выделения, инициализируйте данные, меняйте размер через временный указатель и ровно один раз освобождайте каждый больше не нужный блок.
