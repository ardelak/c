Как пользоваться уроком

Сначала повторим последовательную сортировку, затем разберём потоки и алгоритм, в котором сравнения соседних элементов можно выполнять параллельно без гонки данных.

Каждый блок .c — отдельная полная программа. Для примеров OpenMP используйте компилятор и библиотеку времени выполнения с поддержкой OpenMP, например GCC: gcc -std=c11 -Wall -Wextra -fopenmp program.c -o program. Флаг -fopenmp нужен и при сборке, и при компоновке. С другим компилятором способ настройки может отличаться.

Число потоков можно запросить переменной окружения OMP_NUM_THREADS. В PowerShell: $env:OMP_NUM_THREADS = '4'; .\program.exe. Реальное число потоков зависит также от настроек среды выполнения.

01

Сначала последовательная сортировка

Соседние элементы сравниваются и при необходимости меняются местами.

Пузырьковая сортировка последовательно проходит по массиву. После каждого полного прохода наибольший элемент рассматриваемой части оказывается справа; следующему проходу можно не проверять уже отсортированный хвост.

Вывод
1 2 3 4

Для [4, 1, 3, 2] первый проход даёт [1, 3, 2, 4]: число 4 постепенно перемещается вправо. Следующий проход даёт [1, 2, 3, 4]. Два вложенных цикла выполняют n(n−1)/2 сравнений, то есть время работы O(n²); дополнительная память — O(1).

02

Что делает OpenMP

OpenMP позволяет обозначить параллельные области и распределить работу между потоками одной программы. Директивы записываются как #pragma omp ...; компилятор с поддержкой OpenMP создаёт код параллельного выполнения.

  • #pragma omp parallel создаёт команду потоков, каждый выполняет код параллельной области.
  • #pragma omp for внутри такой области распределяет итерации цикла между потоками команды.
  • #pragma omp parallel for объединяет создание команды и распределение одного цикла.
  • В конце omp for обычно есть неявный барьер: потоки ждут завершения всех итераций. С nowait этого ожидания нет.
ПРОВЕРЬТЕ СБОРКУЕсли компилятор игнорирует директивы или программа собрана без нужного флага, корректность или параллельность исполнения может отличаться от ожидаемой. Используйте поддерживаемый компилятор, флаг OpenMP и проверяйте предупреждения сборки.

В пределах одной итерации порядок обычных операций сохраняется, но порядок выполнения разных итераций между потоками заранее не задан. Вывод из разных потоков может появиться в различном порядке.

03

Пример: сумма с reduction

Вместо одновременного изменения одной суммы каждый поток накапливает свою часть.

Вывод
Сумма: 15
  1. Итерации от 0 до n - 1 распределяются между потоками; массив в этом примере только читается.
  2. reduction(+:sum) создаёт частные накопители для операции сложения и объединяет их с исходной переменной по завершении области.
  3. После окончания параллельного цикла sum содержит результат. В примере значения малы; для произвольных данных нужно отдельно обеспечить отсутствие переполнения.
ПОЧЕМУ НЕ ПРОСТО sum += values[i]?Без reduction несколько потоков могли бы одновременно читать и изменять общую переменную sum. Это гонка данных, а не просто риск получить немного неточную сумму.
04

Почему обычный пузырьковый проход нельзя просто распараллелить

В последовательном цикле соседние итерации работают с пересекающимися парами: при i = 0 это a[0], a[1], при i = 1 — a[1], a[2]. Если два потока одновременно меняют a[1], возникает гонка данных. Результат программы с такой гонкой не определён.

Недостаточно поставить #pragma omp parallel for перед внутренним циклом из первого примера. Нужен алгоритм, в котором одновременно обрабатываемые пары не пересекаются, а между зависимыми этапами есть синхронизация.

05

Параллельная чёт-нечет сортировка

На каждой фазе сравниваем независимые пары, затем ждём завершения фазы.

Чёт-нечет сортировка (odd-even transposition sort) чередует пары (0,1), (2,3), ... и (1,2), (3,4), .... Пары внутри одной фазы не имеют общих индексов, поэтому их можно обрабатывать параллельно. Для массива длины n достаточно n чередующихся фаз.

Вывод независимо от порядка работы потоков
1 2 3 4
ФазаПары индексовМассив после фазы
Начало—[4, 1, 3, 2]
0: чётная(0,1), (2,3)[1, 4, 2, 3]
1: нечётная(1,2)[1, 2, 4, 3]
2: чётная(0,1), (2,3)[1, 2, 3, 4]
3: нечётная(1,2)[1, 2, 3, 4]

Как объяснить безопасность

  1. shared(a, n) разрешает потокам обращаться к одному массиву и его длине. Каждый поток выполняет внешний цикл фаз; его локальные переменные phase и start не являются общими.
  2. omp for распределяет пары текущей фазы. Шаг i += 2 исключает пересечение пар; условие i < n - 1 не позволяет выйти за границу массива.
  3. После каждой фазы неявный барьер omp for гарантирует завершение всех её сравнений до следующей фазы. Поэтому nowait здесь добавлять нельзя.
  4. Переменная temp создаётся внутри итерации и не разделяется между потоками. При n = 0 или n = 1 обменов нет.

В каждый момент фазы один элемент принадлежит не более чем одной паре. Благодаря этому потоки не изменяют одну и ту же ячейку одновременно; барьер защищает переход к следующему набору пар.

06

Сложность и практическая скорость

Обе показанные сортировки делают квадратичное количество сравнений: O(n²). Чёт-нечет сортировка требует n последовательных фаз и барьера после каждой; внутри фазы сравнения независимы. Даже при нескольких потоках синхронизация и организация работы имеют стоимость.

На маленьком массиве параллельный вариант вполне может быть медленнее последовательного. Время зависит от размера данных, числа потоков, среды и компьютера. Для больших массивов обычно выбирают более эффективные алгоритмы, например сортировку слиянием или библиотечный qsort; параллельность сама по себе не исправляет квадратичную сложность.

КАК ПРОВЕРЯТЬИзмеряйте несколько запусков на одних и тех же входных данных, отдельно от печати результатов, и проверяйте корректность отсортированного массива. Не делайте вывод об ускорении по примеру из четырёх чисел.
07

Самопроверка

Задача 1. В массиве из пяти элементов перечислите пары чётной и нечётной фаз.
Показать ответ

Чётная фаза: (0,1), (2,3). Нечётная: (1,2), (3,4). Пары каждой отдельной фазы не пересекаются.

Задача 2. Что нарушится, если убрать барьер между фазами с помощью nowait?
Показать ответ

Один поток может начать следующую фазу до завершения предыдущей. Пары разных фаз пересекаются, поэтому появится гонка за элементы массива.

Задача 3. Запустите пример суммы с одним и несколькими потоками. Должен ли результат отличаться?
Показать ответ

Нет: для этих целых чисел reduction объединяет частные суммы в результат 15. Число потоков и распределение итераций могут различаться.

  • Могу объяснить parallel, for, reduction и барьер.
  • Могу перечислить пары двух фаз и объяснить отсутствие гонки внутри каждой.
  • Понимаю, что параллельная версия не обязательно быстрее на малых данных.

Главное в одном предложении

Распараллеливайте независимые операции, защищайте общие данные и синхронизируйте этапы, между которыми есть зависимости.
