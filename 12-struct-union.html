Как пользоваться уроком

Массивы позволяют объединить множество элементов одного и того же типа. Но в реальных задачах (и на зачете мехмата МГУ) объект почти всегда описывается разнородными характеристиками: например, студент имеет имя (char[32]), возраст (int) и средний балл (double), а вектор или комплексное число состоит из нескольких координат. В этом уроке мы разберем пользовательские составные типы — структуры (struct) и объединения (union), научимся передавать их в функции по указателю, рассчитывать их размер с учетом выравнивания памяти (padding) и сортировать массивы структур.

Сборка примеров: gcc -Wall -Wextra -std=c11 prog.c -o prog.

Структуры (struct): описание, typedef и инициализация

Как объединить разнородные переменные под одним именем и создать собственный тип данных.

Структура (struct) — это составной пользовательский тип данных, который объединяет фиксированный набор переменных (называемых полями или членами структуры) различных типов в единый блок памяти. В структуре все поля существуют одновременно, и каждое поле занимает собственное место в памяти.

Два способа объявить структуру: с тегом и через typedef

  • Через тег структуры: struct Point { int x; int y; }; — создаёт тип с именем struct Point. При объявлении переменных в C придётся каждый раз писать ключевое слово struct: struct Point p1;.
  • Через псевдоним типа typedef: ключевое слово typedef позволяет дать структуре короткое имя (например, Point или Student), чтобы не писать слово struct при каждом использовании.
Вывод
s1:   Анна, возраст 19, балл 4.75, дом (3, 4)
s2:   Борис, возраст 20, балл 4.50, дом (10, -5)
copy: Анна (копия), балл 4.75, empty.age = 0
ЗАПОМНИТЕ: КОПИРОВАНИЕ РАБОТАЕТ, А СРАВНЕНИЕ ЧЕРЕЗ == НЕТ!

В отличие от обычных массивов, структуры одного типа можно копировать простым присваиванием s2 = s1; и возвращать из функций по значению.
Однако структуры нельзя сравнивать оператором == или !=! Запись if (p1 == p2) вызовет ошибку компиляции (из-за возможных «мусорных» байтов выравнивания между полями). Чтобы проверить равенство двух структур, нужно написать функцию, сравнивающую их поле за полем.

ЛОВУШКА: ТОЧКА С ЗАПЯТОЙ ПОСЛЕ ОПИСАНИЯ СТРУКТУРЫ

Определение структуры обязательно заканчивается точкой с запятой после закрывающей фигурной скобки: struct Point { int x, y; };. Если забыть эту ;, компилятор решит, что следующая за структурой строка (например, прототип функции или int main) является переменной этого структурного типа, и выдаст непонятную ошибку компиляции!

Доступ к полям ( . и -> ) и передача структур в функции

Почему структуры почти всегда передают в функции по указателю, а не по значению.

В языке C существуют два оператора для обращения к полям структуры в зависимости от того, работаете ли вы с самой структурной переменной или с указателем на неё:

Оператор Синтаксис Когда используется и что означает
Точка (.) s.age Используется, когда слева стоит сама переменная-структура (типа Student). Обращается напрямую к полю age.
Стрелка (->) p->age Используется, когда слева стоит указатель на структуру (типа Student *). Это синтаксический сахар для выражения (*p).age («сначала разыменуй указатель p, затем возьми поле age»).

Почему скобки в (*p).age обязательны?

Оператор точка . имеет более высокий приоритет, чем унарная звёздочка разыменования *! Поэтому запись *p.age компилятор прочитает как *(p.age) — попытается взять поле age у указателя p и выдаст ошибку компиляции. Чтобы не писать громоздкие скобки (*p).age, в C ввели элегантный оператор стрелка: p->age.

Передача структуры в функцию: по значению vs по указателю

  • По значению (void print_student(Student s)): при вызове функции компилятор копирует в стек все байты структуры (например, 56 или 1024 байта). Любые изменения полей внутри функции меняют только локальную копию и не затрагивают оригинал в main.
  • По указателю для изменения (void birthday(Student *p)): в функцию передается только 8-байтный адрес структуры. Через p->age++ функция напрямую изменяет оригинальную структуру.
  • По константному указателю для чтения (void print_student(const Student *p)): профессиональный стандарт в C! Передается всего 8 байт адреса (мгновенно, без копирования всей структуры), а квалификатор const гарантирует, что функция случайно не испортит поля структуры.
Вывод
Студент: Alex       | Возраст: 19 | GPA: 4.30
Студент: Alex       | Возраст: 19 | GPA: 4.85

Выравнивание данных в памяти (Padding & Alignment)

Почему sizeof(struct) больше суммы размеров её полей и как порядок полей экономит память.

На зачете мехмата МГУ очень часто дают структуру и спрашивают: «Чему равен её sizeof?». Студенты, которые просто складывают размеры полей, получают неверный ответ.

Правило аппаратного выравнивания (Natural Alignment)

Современный процессор читает память не по одному байту, а машинными словами (по 4 или 8 байт). Чтобы процессор мог прочитать переменную за один такт обращения к шине памяти, адрес любой переменной примитивного типа размером K байт должен быть кратен числу K:

  • char (1 байт) — может лежать по любому адресу (кратному 1).
  • short (2 байта) — адрес должен быть четным (кратным 2).
  • int, float (4 байта) — адрес должен делиться на 4 (смещения 0, 4, 8, 12...).
  • double, long long, указатели void * (8 байт на 64-битной системе) — адрес должен делиться на 8 (смещения 0, 8, 16, 24...).

Из-за этого компилятор автоматически вставляет между полями структуры пустые неиспользуемые байты — байты выравнивания (padding), а общий размер всей структуры (sizeof) всегда дополняет в конце (tail padding) так, чтобы он был кратен размеру самого строгого (крупного) поля в этой структуре (чтобы в массиве таких структур второй элемент тоже лежал по выровненному адресу).

Сравнение двух структур с одинаковыми полями (char a, double d, int b)
1) struct BadOrder { char a; double d; int b; };  --> sizeof = 24 байта!
Смещение: 0      1..7 (7 байт)   8..15 (8 байт)   16..19 (4б)  20..23 (4 байта)
         ┌──────┬───────────────┬────────────────┬────────────┬───────────────┐
Память:  │  a   │   PADDING     │    double d    │   int b    │ TAIL PADDING  │
         └──────┴───────────────┴────────────────┴────────────┴───────────────┘

2) struct GoodOrder { double d; int b; char a; }; --> sizeof = 16 байт!
Смещение: 0..7 (8 байт)          8..11 (4 байта)  12 (1б)      13..15 (3 байта)
         ┌──────────────────────┬────────────────┬────────────┬───────────────┐
Память:  │       double d       │     int b      │     a      │ TAIL PADDING  │
         └──────────────────────┴────────────────┴────────────┴───────────────┘
Вывод
Сумма чистых размеров полей: 13 байт

sizeof(struct BadOrder)  = 24 байт
  смещения: a=0, d=8, b=16

sizeof(struct GoodOrder) = 16 байт
  смещения: d=0, b=8, a=12
ЗОЛОТОЕ ПРАВИЛО ПРОЕКТИРОВАНИЯ СТРУКТУР

Чтобы минимизировать потери памяти на «пустые» байты выравнивания (padding), располагайте поля структуры по убыванию размера их базового типа: сначала 8-байтные (double, long long, указатели), затем 4-байтные (int, float), затем 2-байтные (short) и в самом конце — 1-байтные (char).

Объединения (union) и размеченные объединения (Tagged Unions)

Как хранить разные типы в одной и той же области памяти и исследовать внутренние байты числа.

Объединение (union) синтаксически выглядит точно так же, как struct, но работает принципиально иначе: все поля объединения начинаются с одного и того же адреса (смещение 0) и разделяют одну общую область памяти.

  • В struct хранятся все поля одновременно; размер структуры больше или равен сумме размеров всех её полей.
  • В union в каждый момент времени может осмысленно храниться только одно активное поле; запись нового значения в одно поле перезаписывает память всех остальных полей!
  • Размер sizeof(union) равен размеру его самого крупного поля (с учетом выравнивания).
Сравнение памяти struct и union для полей (int i; float f; unsigned char bytes[4])
struct (12 байт — у каждого поля своя память):
┌───────────────────┬───────────────────┬───────────────────┐
│   int i (4 байта) │  float f (4 байта)│  bytes[4] (4 б)   │
└───────────────────┴───────────────────┴───────────────────┘

union (всего 4 байта — общая память для всех трех полей!):
┌───────────────────────────────────────────────────────────┐
│                      int i (4 байта)                      │
├───────────────────────────────────────────────────────────┤
│                     float f (4 байта)                     │
├──────────────┬──────────────┬──────────────┬──────────────┤
│   bytes[0]   │   bytes[1]   │   bytes[2]   │   bytes[3]   │
└──────────────┴──────────────┴──────────────┴──────────────┘

Где применяются union?

  1. Экономия памяти (Размеченное объединение / Tagged Union): когда элемент данных может быть либо целым числом, либо вещественным, либо строкой (но никогда всеми сразу). Объединение заворачивают в структуру вместе с полем-тегом enum, которое помнит, какое именно поле сейчас активно.
  2. Низкоуровневый доступ к байтам и битам: просмотр побайтового представления числа в памяти (например, стандарта IEEE 754 для float или порядка байт Little-Endian).
Вывод
sizeof(union Value) = 4 байт
float = 1.0, в 16-ричном виде = 0x3F800000
Побайтово в памяти (Little-Endian): 00 00 80 3F

После v.i = 65 младший байт v.bytes[0] равен: 65 ('A')

Целое:        42
Вещественное: 3.1415
ЛОВУШКА: ЧТЕНИЕ НЕАКТИВНОГО ПОЛЯ UNION

В обычной логике программы вы всегда должны читать то же самое поле union, в которое последним записывали данные. Если вы записали item.data.d_val = 3.1415;, а затем по ошибке прочитаете item.data.i_val, вы получите бессмысленный набор битов мантиссы вещественного числа!

Массивы структур и сортировка через qsort

Хранение таблиц записей, поиск экстремумов и компараторы для стандартной быстрой сортировки.

Объединив структуры и массивы, мы получаем главный инструмент для работы с табличными данными в C — массив структур (например, Student group[100];). Каждая ячейка такого массива group[i] является полноценной структурой, а обращение к её полям выглядит как group[i].gpa.

Сортировка массива структур функцией qsort

На зачете мехмата часто требуется отсортировать массив записей (студентов, товаров, отрезков) по какому-либо полю. В стандартной библиотеке <stdlib.h> есть готовая функция быстрой сортировки qsort:

void qsort(void *base, size_t nmemb, size_t size, int (*compar)(const void *, const void *));

Чтобы qsort знала, как сравнивать две ваши структуры, вы передаете ей функцию-компаратор, которая приводит обобщенные указатели const void * к типу const Student * и сравнивает нужные поля.

Вывод
Рейтинг студентов после сортировки:
1. Алексей    (возраст: 20) — GPA: 4.90
2. Вера       (возраст: 19) — GPA: 4.90
3. Анна       (возраст: 19) — GPA: 4.70
4. Борис      (возраст: 20) — GPA: 4.10
ЛОВУШКА В КОМПАРАТОРЕ ДЛЯ DOUBLE

Функция-компаратор для qsort обязана возвращать int (отрицательное число, 0 или положительное число). Никогда не пишите return s1->gpa - s2->gpa; для вещественных чисел! Если разница равна 0.3, при приведении к int дробная часть отбросится, и функция вернет 0 (будто числа равны!). Всегда используйте сравнения или идиому (a > b) - (a < b).

Ручной расчет для TelemetryRaw:

  • sensor_id (1 байт): смещение 0. Следующее поле double reading требует адреса, кратного 8, поэтому байты 1..7 (7 байт) уходят под padding.
  • reading (8 байт): смещение 8..15.
  • flags (1 байт): смещение 16. Следующее поле int timestamp требует адреса, кратного 4, поэтому байты 17..19 (3 байта) — padding.
  • timestamp (4 байта): смещение 20..23.
  • error_code (2 байта): смещение 24..25. Чтобы общий размер структуры делился на 8 (размер double), в конец добавляется ещё 6 байт tail padding (байты 26..31). Итог: 32 байта!
