Общая структура С-программы

Директивы препроцессора → объявления → функции → main().

Программа на C состоит из функций; выполнение начинается с main. Обычный порядок: подключение заголовков (#include), макросы (#define), типы, глобальные переменные, прототипы функций, main, определения остальных функций.

Три стадии сборки

Код на C проходит три стадии: препроцессор, компиляция и линковка. Прототип функции нужен, чтобы на этапе компиляции компилятор уже знал «форму» функции (её сигнатуру), даже если тело написано ниже или в другом файле.

Схема сборки
structure.c ──► [препроцессор] ──► [компилятор] ──► structure.o ──► [линковщик] ──► structure
                #include, #define    типы, сигнатуры    объектный код    + libc (printf ...)   исполняемый файл

1) Препроцессор

Обрабатывает директивы, начинающиеся с #: #include, #define, #ifdef и т.п. Для нашего примера:

  • #include <stdio.h> — вставляет содержимое заголовочного файла stdio.h прямо в ваш файл;
  • #define PI 3.14159 — везде в коде заменяет PI на 3.14159.

Результат — один большой «раскрытый» исходный файл, где нет #include и #define, но есть весь код заголовков и подставленные макросы. Посмотреть его можно командой gcc -E structure.c.

2) Компиляция

Берёт результат работы препроцессора и переводит его в объектный код (машинные инструкции для конкретного процессора), но ещё не в готовую программу. Проверяет типы, синтаксис, соответствие сигнатур функций и т.д. Для каждого исходного файла создаётся свой объектный файл (например, main.o, area.o, если функции лежат в разных файлах): gcc -c structure.c.

Здесь и важен прототип. Строка double area(Circle c); говорит компилятору:

  • есть функция с именем area;
  • она принимает один параметр типа Circle;
  • возвращает double.

Благодаря этому в main можно написать area(c) до того, как компилятор увидит определение double area(Circle c) { ... }. Без прототипа компилятор либо выдал бы ошибку «неизвестный идентификатор area», либо (в старом стандарте C) предположил бы неверную сигнатуру, что привело бы к ошибкам линковки или странному поведению. Прототип — это «контракт»: он фиксирует, как правильно вызывать функцию, чтобы компилятор мог проверить все вызовы.

3) Линковка (компоновка)

Берёт несколько объектных файлов (например, main.o, area.o, плюс стандартные библиотеки вроде libc) и соединяет их в один исполняемый файл. Линковщик разрешает «внешние ссылки»: в main.o есть вызовы area и printf, но их адреса ещё неизвестны. Линковщик находит определение area в area.o, а printf — в стандартной библиотеке, и подставляет реальные адреса. Если какой-то функции не хватает (например, забыли файл с определением area), линковщик выдаст ошибку undefined reference to 'area'.
