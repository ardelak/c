Цель урока

Разобраться с двумя важнейшими концепциями, которые определяют поведение переменных в программе: где переменную можно использовать (область видимости) и когда она существует в памяти (время жизни). Понимание этих механизмов — включая модификатор static и затенение переменных (shadowing) — обязательно для успешной сдачи зачета и написания безопасного кода без утечек и ошибок доступа к памяти.

Область видимости и время жизни

Две разные оси существования переменной.

В языке C каждая переменная характеризуется двумя основными свойствами, которые часто путают:

  • Область видимости (Scope): Это пространственное свойство. Оно определяет ту часть исходного кода, в которой имя переменной известно и может быть использовано. Если вы попытаетесь обратиться к переменной вне ее области видимости, компилятор выдаст ошибку (например, 'x' undeclared).
  • Время жизни (Lifetime): Это временное свойство во время выполнения программы. Оно определяет, с какого момента для переменной выделяется память и в какой момент эта память освобождается (уничтожается).

Локальные и глобальные переменные

Стек вызовов против статического сегмента данных.

Локальные переменные создаются при входе в блок (например, в тело функции) и уничтожаются при выходе из него. Если локальная переменная не инициализирована явно, она содержит "мусор" (случайные данные, оставшиеся в памяти).

Глобальные переменные объявляются вне всех функций. Они автоматически инициализируются нулем (0), если им не задано значение. Однако, использование глобальных переменных считается плохой практикой (за исключением констант), так как любая функция может их изменить, что усложняет отладку.

ЗАПОМНИТЕ: static VS global

Что происходит, когда имена совпадают.

В C можно открывать новые блоки кода { ... } внутри других блоков (например, внутри if, циклов for или просто так). Каждая переменная видна только в том блоке, где она объявлена, и во всех вложенных в него блоках.

Если во вложенном блоке объявить переменную с таким же именем, как во внешнем, произойдет затенение (shadowing). Внешняя переменная временно станет недоступной, пока не завершится вложенный блок.

Модификатор static: Сохранение состояния

Локальная видимость, но глобальное время жизни.

Ключевое слово static полностью меняет правила игры для локальных переменных. Если объявить локальную переменную как static, она не будет уничтожена при выходе из функции. Она сохранит свое значение между вызовами функции!

При этом её область видимости останется локальной — она будет видна только внутри своей функции.

ЗАПОМНИТЕ: static VS globalИспользование локальных static переменных гораздо безопаснее глобальных. Глобальную переменную может испортить любая другая функция в программе. Локальную static переменную может изменить только та функция, внутри которой она объявлена, при этом состояние (значение) надежно сохраняется.
ЛОВУШКА ДЛЯ ЗАЧЕТА: ВОЗВРАТ УКАЗАТЕЛЯ
Никогда не возвращайте из функции указатель на обычную локальную переменную! Как только функция завершится, память очистится, и указатель станет "висячим" (dangling pointer), указывая на мусор.

НЕПРАВИЛЬНО: int* get_ptr() { int a = 5; return &a; }
ПРАВИЛЬНО: Либо возвращайте значение (return a;), либо выделяйте память динамически через malloc, либо делайте переменную статической: static int a = 5; return &a; (хотя последнее тоже считается плохим тоном в многопоточных программах).

Задача 3: Анализ области видимости (Code Review).
Внимательно изучите следующий код. Что будет выведено на экран в результате его работы? Почему компилятор не выдаст ошибку переопределения переменной val? Объясните механизм затенения (shadowing) на этом примере. 
int val = 100;
int main(void) {
    int val = 50;
    {
        int val = 10;
        printf("%d ", val);
    }
    printf("%d ", val);
    return 0;
}
Показать решение Задачи 3

Вывод программы: 10 50

Разбор:

  • В коде объявлено три абсолютно разные переменные, которым разработчик (в качестве плохой практики) дал одинаковое имя val.
  • Глобальная переменная val = 100 перекрывается (затеняется) локальной переменной val = 50 сразу при входе в main.
  • Когда открывается вложенный блок { ... }, внутри него объявляется третья переменная val = 10. Она затеняет переменную из main. Поэтому первый printf выводит 10.
  • Как только вложенный блок закрывается }, переменная val = 10 уничтожается. Область видимости возвращается к переменной val = 50 из функции main. Поэтому второй printf выводит 50.
  • Глобальная val = 100 так и осталась нетронутой и недоступной из-за полного перекрытия имен.

Задача 5: Возврат указателя (Поиск ошибки).
Студент на зачете написал следующую функцию, которая должна возвращать указатель на максимальное из двух переданных чисел. Однако при компиляции с флагом -Wall компилятор выдал предупреждение (Warning), а программа упала с ошибкой при выполнении.
Найдите ошибку в коде и объясните причину (опираясь на правила времени жизни локальных переменных). Как исправить этот код? 
int* get_max_pointer(int a, int b) {
    int max;
    if (a > b) {
        max = a;
    } else {
        max = b;
    }
    return &max;
}
Показать решение Задачи 5

В чем ошибка:

Студент возвращает адрес (&max) локальной переменной max. Проблема в том, что время жизни переменной max (которая выделяется на стеке) заканчивается ровно в момент выполнения инструкции return и выхода из функции. Память, где лежало это значение, освобождается и может быть немедленно перезаписана другими данными операционной системы.

Функция main получит указатель на недействительную (уничтоженную) область памяти. Попытка прочитать данные по этому адресу приведет к неопределенному поведению (UB), выводу "мусора" или ошибке Segmentation Fault.

Как исправить:

Никогда не возвращать указатели на локальные auto-переменные. Если нужно вернуть само значение, измените сигнатуру функции, чтобы она возвращала int, а не int*.

// Исправленный вариант: возвращаем значение, а не адрес

int get_max(int a, int b) {
int max = (a > b) ? a : b;
return max; // Возвращается КОПИЯ значения, что абсолютно безопасно
}
