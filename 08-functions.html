Цель урока

Освоить модульное программирование на C. Функция — это фундаментальный строительный блок любой программы на C (ведь даже точка входа main — это функция). Мы разберем, как компилятор узнает о функции до ее вызова (прототипы), как передавать данные в функцию (аргументы по значению) и как функция может вызывать саму себя (рекурсия). Эти концепции жизненно важны для сдачи зачета на мехмате, так как они ложатся в основу работы со структурами данных и алгоритмами.

Прототипы (Объявления) и Определения Функций

Как компилятор C узнает о функции до ее фактического кода.

В языке C существует строгое правило: компилятор должен знать "форму" функции (ее сигнатуру) до того, как вы попытаетесь ее вызвать. Это связано с тем, что код компилируется сверху вниз (в один проход). Если вы вызываете функцию calculate() в main, а ее код написан ниже, компилятор выдаст ошибку (или неявное предупреждение), так как не будет знать, сколько аргументов она принимает и что возвращает.

Решение — использование прототипов функций (Function Prototypes).

  • Прототип (Объявление / Declaration): Сообщает компилятору имя функции, тип возвращаемого значения и типы принимаемых параметров. Тела у прототипа нет, он заканчивается точкой с запятой ;. (Например: int add(int a, int b);). Имена переменных в прототипе писать необязательно, важны только типы.
  • Определение (Definition): Это сама функция с ее логикой внутри фигурных скобок { ... }.
ЗАПОМНИТЕ: ПРАВИЛО ПРОТОТИПОВ
На зачете всегда пишите прототипы функций перед main(), а их реализацию — после. Это классический, читаемый и безопасный стиль написания программ на C. Прототипы обычно группируют и выносят в заголовочные файлы (.h).

Передача аргументов "По Значению" (Pass by Value)

В C функции работают с копиями данных, а не с оригиналами.

Это важнейшая концепция для сдачи зачета. Когда вы передаете переменную в функцию (например, calculate(x)), язык C всегда копирует значение x в новую, локальную переменную внутри функции.

Следовательно: любые изменения, которые функция делает со своими аргументами, не влияют на оригинальную переменную в вызывающем коде.

СОВЕТ: КАК ИЗМЕНИТЬ ОРИГИНАЛ?
Если вы хотите, чтобы функция действительно изменила исходную переменную (например, функция обмена значений swap(a, b) или функция, возвращающая несколько результатов), вам нужно передавать адреса переменных с помощью указателей (swap(&a, &b)). Эту тему (Pass by Reference через указатели) мы детально разберем в уроке про указатели.

Стек вызовов (Call Stack)

Как программа помнит, куда возвращаться.

Когда одна функция вызывает другую, выполнение первой функции "ставится на паузу". Программа должна запомнить, где она остановилась, чтобы вернуться туда после завершения вызванной функции. Этот процесс управляется структурой данных в оперативной памяти, которая называется Стек Вызовов (Call Stack).

  1. При вызове функции в Стек добавляется новый "кадр" (Stack Frame). В нем сохраняются аргументы функции, её локальные переменные и адрес возврата.
  2. Если эта функция вызывает третью, в Стек добавляется еще один кадр поверх предыдущего.
  3. Когда функция завершается (достигает return или конца блока }), её кадр "снимается" (уничтожается) со Стека, локальные переменные стираются из памяти, а программа возобновляет работу с сохраненного адреса возврата.
ЛОВУШКА ДЛЯ ЭКЗАМЕНА (STACK OVERFLOW)
Размер Стека строго ограничен (обычно несколько мегабайт). Если функции будут бесконечно вызывать друг друга, Стек переполнится, и программа аварийно завершится с ошибкой Stack Overflow. Это частая проблема при неправильном написании рекурсивных функций.

Рекурсия (Recursion)

Когда функция вызывает саму себя.

Рекурсия — это мощный инструмент для решения задач, которые можно разбить на более мелкие подзадачи того же типа (например, обход деревьев, фракталы, алгоритмы сортировки вроде QuickSort). Вместо использования циклов (итерации), функция вызывает саму себя.

Золотое правило рекурсии: Любая рекурсивная функция обязана иметь Базовый случай (Base Case) — условие, при котором рекурсия останавливается и функция возвращает результат без дальнейших вызовов. Без базового случая функция будет вызывать себя бесконечно, что приведет к переполнению стека (Stack Overflow).
